# 06.4 — Authentication & Authorization Architecture

# Purpose

Authentication verifies the identity of every user accessing SynapseHR.

Authorization determines which resources that authenticated user may access.

The authentication subsystem must remain independent from business logic and reusable across all modules.

---

# Security Goals

The authentication system shall:

- Verify user identity securely.
- Protect all private endpoints.
- Support Role-Based Access Control (RBAC).
- Prevent privilege escalation.
- Support token refresh.
- Be provider-independent.
- Scale to multiple organizations.

---

---

# Login Process

The login process shall perform:

1. Validate request schema.
2. Locate user.
3. Verify password hash.
4. Verify account status.
5. Verify organization status.
6. Generate access token.
7. Generate refresh token.
8. Record login event.
9. Return authenticated session.

---

# Password Storage

Passwords shall never be stored in plain text.

Requirements:

- bcrypt hashing
- Unique salt
- Configurable work factor

Passwords must never be logged.

---

# JWT Strategy

Two-token architecture.

Access Token

Purpose

API authentication

Lifetime

15–30 minutes

Refresh Token

Purpose

Issue new access token

Lifetime

7–30 days

Refresh tokens should be revocable.

---

# JWT Claims

Every access token contains

User ID

Organization ID

Role

Issued Time

Expiration Time

Token ID

No sensitive personal information shall be embedded.

# Ownership Validation

Some resources require ownership checks.

Examples

Employees may:

View their own profile.

Managers may:

View profiles of employees reporting to them.

HR/Admin may:

View all employees.

# Logout

Logout should:

Invalidate refresh token.

Record audit event.

Clear client session.

Access tokens naturally expire.

# Account Status

Supported states

Active

Suspended

Locked

Pending Verification

Disabled

Authentication must reject non-active accounts.

---

# Multi-Tenant Support

Every authenticated request belongs to exactly one organization.

Users must never access another organization's data.

Organization validation occurs before business logic.

---

# Security Rules

Never expose:

Password Hash

JWT Secret

Refresh Tokens

Internal Security Metadata

---

# Definition of Completion

Authentication is complete when:

- JWT authentication works.
- RBAC is enforced.
- Ownership validation exists.
- Passwords are securely stored.
- Refresh flow operates correctly.
- Audit logs capture all security events.
