# 06.9 — Backend Engineering Rules

# Purpose

This document establishes mandatory engineering standards for every backend module.

These rules ensure consistency, maintainability, and long-term scalability.

---

# Code Quality

Every class must have one responsibility.

Every function should perform one logical task.

Avoid duplicate business logic.

Prefer composition over inheritance.

---

# Typing

All public functions require

Type Hints

Return Types

Strong typing is mandatory.

---

# Documentation

Every public class and function should include

Purpose

Parameters

Return Value

Exceptions

---

# Testing

Every module requires

Unit Tests

Integration Tests (where applicable)

Critical business workflows require end-to-end tests.

---

# Security

Never trust client input.

Validate all requests.

Use parameterized queries.

Protect secrets.

Apply least privilege.

---

# Performance

Avoid N+1 queries.

Paginate large datasets.

Cache expensive operations where appropriate.

Keep API latency low.

---

# AI Integration

AI must access business capabilities only through approved tools and services.

AI must never bypass business validation or repository abstractions.

---

# Definition of Completion

The backend implementation is considered complete only when:

- Architecture rules are respected.
- Tests pass.
- Documentation exists.
- Security requirements are satisfied.
- Performance targets are met.
- No placeholder implementations remain.
